# W1 離線資料契約

依 `SPEC_dual_hand_v1.md` §2、§3、§5.1、§5.2、§5.4 生成；本目錄不含 Android 行為變更。
來源只讀，不下載詞庫、不重跑既有 Rime extractor、不更新既有音節全集。

## 重跑

在工作樹根目錄執行：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 native/dual_hand/generate.py --audit-dir /home/simon/.claude/audit/ime_dual_hand_20261011/w1
```

需既有 Python 3、NumPy、SciPy（本次 Python 3.12.3、SciPy 1.17.1）；沒有安裝新依賴。
輸入 SHA-256 先對照既有 `native/zhuyin_t9_core/generated/MANIFEST.json`，再重建415音節的字數與合計頻分，結束時再核來源未變。
`MANIFEST.json` 記來源、產生腳本與所有 TSV 的 SHA-256、bytes；審查目錄存斷言、統計、完整對照表。
字頻是產品排序分數，混用 DB 與 Rime 補字權重，並非真實輸入行為或臺灣語料頻率。

## TSV 格式（輸出：app/src/phone/assets/dual_hand/）

全部 UTF-8、LF、有一列欄名，tab 分欄，無 BOM；以字元排序打破等頻並列。

|檔名|欄位與契約|
|---|---|
|dual_hand_map.tsv|`state,key,gesture,syllable`；25狀態×7鍵×5手勢＝875列，含空格。`state`為聲母、`Ø`或起頭`ㄧ/ㄨ/ㄩ`；`key`為`A`至`F`或`Ø`；`gesture`為`tap/left/up/right/down`；空音節＝不輸出。音節保留聲母、介音及韻母，不含聲調。|
|left_hand.tsv|`key,gesture,state`；6鍵×5手勢＝30列；空狀態＝無作用。只涵蓋六個音位鍵，不含功能鍵。|
|draft_chars.tsv|`syllable,char`；415列，每音節一個字；同字同音節的正字頻跨聲調加總後取第一名。|
|grid_chars.tsv|`syllable,char1,...,char9`；415列，每音節最多九個不同字，與草稿用同一排序；不足九字的尾欄空白，不捏造補字。|
|phrase_words.tsv|`syllables,word,frequency,rank`；無聲調音節間以一個ASCII空白分隔；每列一個2–4字詞；同音節序列、同詞跨聲調詞頻加總；同序列依頻率降序、等頻依字元升序，rank從1開始。|

消費端依完整音節序列查詢；緩衝長度2–4才查，顯示rank≤3，整段完全相同才匹配，不以聲母縮寫或前綴匹配。長度1或≥5不出短詞。
基準字與同音網格包含兩個不可達音節，供41鍵／校正功能查詢。候選詞資料不接AI。
字數以Unicode碼點計，不是UTF-16單元數；來源含非BMP字，例如ㄟ網格的「𡅅」，消費端不能假設每字只占一個UTF-16單元。

## 來源與選擇

- 合法音節：`native/zhuyin_t9_core/generated/legal_syllables.tsv`，415個。
- 字頻：`app/src/phone/assets/zhuyin_initials.db` 的 `words(word,pronunciation,frequency)`，採單字、合法結構、正頻率。
- 單字補充：`native/zhuyin_t9_core/rime_single_chars.tsv`，只補上述DB完全未有的字，沿用既有generator政策；不是替現有多音字補漏讀音。
- 短詞選DB：已具有完整注音與詞頻；2/3/4字來源分別79,294/28,784/25,258列，合計133,336列。排除非正頻23,009列；接受110,327列，合併後107,300個「序列、詞」對，74,824組序列，3,547,192 bytes。
- Rime盤點：產品有 `app/src/phone/assets/rime/build/terra_pinyin.table.bin`（17,573,572 bytes）與 `terra_pinyin.prism.bin`（258,560 bytes）；既有 `extract_rime.py` 只解出單字補表。短詞若選此來源須另解整份二進位詞庫、轉拼音，這輪未做；本輪直接用已有注音的DB，無新增外部資料。
- 詞庫保留來源的詞及排序，不因驗收題人工加詞或提權；「確認」存在，「條款」1075分，排在「調寬」1分之前。
- 原詞庫字形未另外篩繁體／現代常用字，例如ㄉㄨㄟ網格含「対」，均按指定來源字頻保留；這個來源限制交協調者決定後續政策。

## 分配規則與規格交界

先固定合法錨點及四個例字，再讓剩餘音節在空方向間最佳化；不跨A–F/Ø鍵搬音節。
只有一般聲母的超容量格可依§3.3-5捨最低頻音節；ㄋE捨ㄋㄨㄣ630分、ㄌE捨ㄌㄩㄢ7分，兩者皆≤第10百分位3215分。
ㄌㄩㄢ原是合法↓錨點，但特定罕用例外優先於一般錨點，才可釋出容量；未放寬四例硬限制。
B鍵§3.3-6優先於通常的點主韻／左對立韻（包括Ø），只重排開口韻的點／左，不改介音主韻錨點；起頭ㄧ/ㄨ/ㄩ的B鍵則依§3.3-1特定表。
起頭狀態的其餘方向保持空；Ø狀態保留主韻與介音主韻，未覆蓋的介音對立韻由起頭狀態提供，只有未覆蓋的裸韻（ㄝ）補入Ø的空格；有＝ØD↓是明文例外。
ㄐㄑㄒ點不能空的規則與合法↑錨點同時保留：最高頻音節若已在↑，點與↑可重複；Ø鍵點與↑也依§3.4重複。規格只限制同一格不能放兩個音節，未禁止同音節多路徑。

## 一致度與最優證明

採用的計分假設：韻母含介音（沿用R1的39種完整韻母）；同一音節若有n條路徑，每條分得其合計字頻的1/n，避免多路徑重複灌大頻率。
每個韻母各方向的分數加總，取最高方向分數÷該韻母總分，為「方向不變比例」。整體＝所有韻母最高方向分數之和÷全部可達音節字頻。
25狀態全部納入（含右手直出與起頭狀態）；方向種類統計則列所有實際非空路徑，重複路徑不刪除。不可達音節另外列出，分母不含其637分。
以混合整數規劃同時選各韻母的主方向與空位分配，固定錨點不動；整數尺度2消除平分的小數。HiGHS回傳status=0、mip_gap=0，解的分數再由實際表重算比對，證明在上述分配空間與口徑內達全域最優。
最優一致度84.482322%，規格≥90%是可推翻的預測，本次未達。只計21聲母為90.178843%；只保留自然左手狀態路徑（不含Ø直出替代）為81.074000%；這兩個值是附帶口徑，未另做最佳化。
取消四個例字限制、其餘同規則重算可達85.276832%；保留四例代價0.794510百分點。這只是反事實計算，不交付其映射。

## 點滑比例

按每音節字頻加權，不以每字種類等重。零聲母帶介音採起頭ㄧ/ㄨ/ㄩ；裸韻採Ø；一般聲母照左手表。右手重複路徑選點優先，其餘固定依left/up/right/down順序挑第一條；每音節只計一條雙手路徑。
詳細路徑存審查目錄 `canonical_routes.tsv`，權重總數28,727,140；未計罕用的637分，覆蓋全部來源頻分99.997783%。
左手點32.339143%／滑67.660857%，右手點52.630655%／滑47.369345%，不同於文章左25/75、右28/72。
右手點偏高受到起頭介音及ㄐㄑㄒ點補位影響；這是固定打法的詞庫加權估計，未測人實際採哪條路徑、觸控準確度、速度、疲勞或語料分布。
